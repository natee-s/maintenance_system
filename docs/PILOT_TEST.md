# Recommended pilot test

Use one site, 20–30 assets, two technicians, one supervisor, one requester and one storekeeper. Prepare actual locations, asset/part/failure categories, UOMs, opening counts and 3–5 PM templates. Keep accounting/procurement and external notification channels outside this pilot.

1. Confirm login/role isolation with each role; deactivate a test user and verify existing session access is denied. Confirm another active admin exists before changing admin roles.
2. Print QR labels for five machines. Scan on physical Android/iOS over HTTPS in the workshop, log in when logged out, check the correct machine and preselected request. Try invalid/archived QR and manual entry.
3. Requester reports a stopped machine with observed time and photo. Supervisor reviews priority/reason, converts once and attempts a second/concurrent conversion. Confirm exactly one WO and linked primary downtime.
4. Assign technician1; technician2 must not access execution/photo. Start, pause with reason, resume, wait for part and resume. Record findings/action/failure category, comment/photo and complete. Technician cannot close. Supervisor returns for rework with reason, then closes. Open downtime requires acknowledgement; supervisor records actual machine recovery with reason. History and period-clipped downtime must agree.
5. Create a PM checklist with CHECK/TEXT/NUMBER/PASS_FAIL and a fail-note/photo rule. Create weekly/monthly/custom plans, generate twice, verify one WO per plan/date and stable old snapshot after template edit. Complete checklist on mobile; required/bounds/fail evidence must block incomplete completion. Check calendar and fixed next due.
6. Storekeeper posts opening/receipt and adjustment with reason. Supervisor reserves five units; storekeeper issues three and returns one. Verify onHand decreased by two, remaining reservation two and available balance; close/cancel releases remaining reservation. Reject over-issue/over-return/fractional pieces and concurrent last-stock oversubscription. Trace WO → asset → part usage → immutable ledger/actor.
7. Filter dashboard dates/site/area/category, trend grain and ledger dates. Confirm cancelled PM excluded from rate, current statuses versus period completion and ended/ongoing downtime. Separate units in inventory summary. Verify mobile More reaches PM/inventory and own notification read status.
8. Run a PostgreSQL + private-storage restore drill on a separate pilot-host database/directory, reconcile balances and download restored evidence. Measure load/latency at expected concurrency and test error/empty/keyboard states.

Record defects with role, record/business code, time, expected/actual behavior and sanitized screenshot. Success measures: correct machine on every scanned QR, no duplicate conversions/PM, no negative stock, all issue/returns traceable, complete audit for critical operations and shop-floor task completion without assistance. Agree a pilot period and follow-up review with the plant team.
